# План реализации: FPGA-синтезатор для АВК-6

ТЗ: [`trs.md`](trs.md). Требования к схеме: [`hw-requirements.md`](hw-requirements.md). Эскиз панели: [`panel-sketch.svg`](panel-sketch.svg).

Принцип: каждый этап заканчивается работающим устройством, которое можно подключить к АВК и послушать.
Этапы 1–6 — на Tang Nano 9K (макет на модулях), с 7-го — на 20K. Параллельно идёт трек «железа» (H1–H4, KiCad; требования к узлам — `hw-requirements.md`, схему и разводку рисует автор проекта).

## Структура репозитория (предложение)

```
fpga/
  rtl/        # SystemVerilog: audio/, voice/, midi/, bus/, slots/, periph/, cpu/
  boards/     # top-level и .cst для tang_nano_9k, tang_nano_20k
  sim/        # тестбенчи Verilator (C++), стимулы MIDI, анализ WAV на Python
  model/      # Python-модели DSP-блоков, генерация эталонных WAV
sw/           # прошивка RISC-V (C): загрузчик, драйверы, меню, распределитель голосов
hw/           # схема и плата (KiCad), чертёж панели
fw/           # существующая прошивка midi2aux (Arduino) — без изменений
```

## Этапы

### Этап 0. Инфраструктура
1. **CI в GitHub Actions — первым делом**, до первой строчки RTL:
   - линт RTL (`verilator --lint-only -Wall`);
   - симуляция в Verilator: тестбенч подаёт на вход поток MIDI-байтов (и сигналы ВХ1/ВХ2 из файлов), снимает выход I2S → WAV;
   - анализ на Python: спектр (частота основного тона против таблицы нот, гармоники, шум), осциллограммы, огибающие; проверки с допусками → pass/fail;
   - графики (PNG) и WAV — артефакты сборки, их можно скачать и послушать;
   - сборка C-прошивки RISC-V (`riscv-none-elf-gcc` / `riscv64-unknown-elf-gcc`).
2. Каркас `fpga/`, `sw/`, `hw/`, скрипты сборки (`make lint`, `make sim`, `make fw`).
3. Проекты Gowin EDA для 9K и 20K (`fpga/boards/`), обёртки примитивов (PLL, BSRAM). Битстрим собирается локально.
4. Python-модели: NCO, ADSR, SVF → эталонные WAV для сравнения с RTL.
- **Готово, когда:** CI зелёный на заглушечном модуле (генератор синуса → I2S → WAV → проверка частоты), «мигалка» из Gowin EDA работает на 9K.
- **Статус:** сделано всё, кроме проверки на железе: CI (`.github/workflows/fpga-synth.yml`), `make lint/sim/model/fw/test`,
  `stub_core` (синус + пила → I2S, эхо MIDI, мигалка), модели NCO/ADSR/SVF, скрипты `gw_sh` для 9K и 20K.
  Осталось у автора: собрать битстрим в Gowin EDA и проверить «мигалку» на 9K. См. `fpga/README.md`.
- **Решения этапа 0:**
  - sys_clk = 99 МГц (rPLL 27 · 11 / 3), BCK = sys_clk / 32, fs = 48 339.84 Гц (+0.7 %);
  - таблица синуса — четверть периода, 1024 × 17 бит, без интерполяции (THD+N ≈ −67 дБ); генерируется из модели
    в виде `case`-ROM (`make luts`), а не `$readmemh` — нет зависимости от путей в Verilator/Gowin/yosys;
  - стимулы MIDI — текст `<время_мс> <байты hex>`; входы ВХ1/ВХ2 из файлов подключаются в тестбенч вместе
    с моделью АЦП (этап 6);
  - распиновка I2S/MIDI на макете — предварительная (HO-01): 9K и 20K — выводы 25–29.

### Этап 1. Звук наружу (паритет с midi2aux)
- PLL, `audio_tick` ≈ 48 кГц, I2S TX → модуль PCM5102A.
- UART RX 31250 + парсер MIDI (running status) → FIFO событий.
- Временно: один голос, меандр, реакция на последнюю ноту — прямо в RTL.
- Выходной каскад на макетке: ОУ ±15 В → ±10 В. Проверить DC-тракт PCM5102A (O-09).
- **Готово, когда:** клавиатура играет одноголосно через АВК, как старый midi2aux.
- **Статус:** RTL и тесты готовы (`mono_core`, юнит-тесты `uart_rx`, `midi_parser`, `sync_fifo`, `pitch2inc`,
  системный тест нот, pitch bend и задержки); board-top 9K/20K собирают `mono_core`. Осталось на железе:
  PCM5102A + выходной каскад, проверка DC-тракта (O-09).
- **Решения этапа 1:**
  - формат отсчётов Q2.16 в 18 битах: 1.0 = 2^16 = МЕ (±10 В), запас до ±2 МЕ внутри тракта;
    на выходе `dac_scale`: код ЦАП = x · 1.6, т.е. МЕ = 0.8 FS ЦАП (±12.5 В);
  - высота тона в лог-шкале: `pitch = log2(inc) · 2^16` (21 бит), модуляции складываются в этой шкале,
    перевод в инкремент — `pitch2inc` (таблица 2^x 1024 точки + линейная интерполяция, ошибка < 0.02 цента);
  - парсер MIDI отдаёт Note On с velocity 0 как Note Off `8n kk 40`, System Realtime — отдельными событиями.

### Этап 2. Процессор
- PicoRV32 + BSRAM + шина + UART-отладка + таймер.
- Загрузчик: прошивка по UART (BL702) и из SPI-флеша.
- MIDI FIFO читается CPU; `printf` событий в UART.
- **Готово, когда:** C-прошивка обновляется за секунды без пересборки битстрима и печатает ноты.
- **Статус:** RTL, прошивка и тесты готовы: `synth_core` (PicoRV32 RV32IMC, RAM 32 КБ, boot ROM 4 КБ, UART,
  таймер, GPIO, FIFO MIDI, sysinfo, SPI-флеш), загрузчик (UART + SPI-флеш), `sw/tools/load.py`.
  Системные тесты в Verilator: загрузка, запись/чтение флеша, повторный вход из прошивки, печать MIDI.
  На железе: проверить пины UART/флеша (предварительные) и смещение образа во флеше.
- **Решения этапа 2:** шина — нативный интерфейс PicoRV32 с ответом за 1 такт; boot ROM — генерируемый
  case-ROM из `sw/boot` (без путей к файлам в Gowin); в симуляции RAM можно заполнить сразу (`RAM_INIT`),
  минуя загрузчик; прерывания пока не используются (опрос).

### Этап 3. Полифония
- Голосовой движок с мультиплексированием по времени, параметр `NUM_VOICES`.
- 2 NCO на голос (пила, меандр/PWM, треугольник, синус), шум, смесь, расстройка.
- ADSR1 → громкость; velocity → громкость.
- Сумматор с запасом разрядности + софт-лимитер.
- Распределитель голосов на C: свободный голос / кража; pitch bend, mod wheel.
- Замер ресурсов 9K: сколько голосов влезает. Сравнение Gowin EDA и yosys+nextpnr по LUT и Fmax.
- **Готово, когда:** аккорды и Rush E на 16+ голосах без щелчков и переполнений.
- **Статус:** RTL, прошивка и тесты готовы. Движок `voice_engine` (побитово = `synthmodel.voice`): 2 NCO
  (пила, меандр/PWM, треугольник, синус) + шум, смесь, SVF Chamberlin с 2× передискретизацией (ФНЧ/ПФ/ФВЧ),
  ADSR1 → VCA, ADSR2 → срез, velocity → громкость и срез, сумма + мягкий лимитер. Прошивка: распределитель
  голосов (`fw/voice_alloc.c`), пересчёт параметров (`fw/params.c`), MIDI → регистры (`fw/synth.c`),
  неблокирующий лог; хост-тесты всех трёх. Системный тест: аккорд, bend, кража голосов.
  Осталось на железе: замер ресурсов 9K/20K, Fmax (цепочка умножитель → сумматор → регистр операнда
  за один такт — при нехватке Fmax вставить регистр, модель не меняется), сравнение с yosys+nextpnr.
- **Решения этапа 3:**
  - голоса считаются последовательно, 22 такта на голос (32 голоса ≈ 700 из 2048 тактов отсчёта);
  - огибающие — одно-полюсные экспоненты с коэффициентом «мантисса 17 бит + сдвиг» (времена 1 мс…10 с
    без потери точности); release целится в −1e-3, поэтому заканчивается ровно за время R;
  - фильтр — Chamberlin 2×, f = 2θ − θ³/3 (θ = π·fc/2fs), демпфирование ограничено `q ≤ 2 − f − 1/16`
    для устойчивости; срез до 0.34·fs (16 кГц);
  - ретриггер — бит-переключатель (одна сторона пишет каждый регистр);
  - осцилляторы свободно бегущие (без сброса фазы): при расстройке ГЕН2 основной тон «биет».

### Этап 4. Тембр
- SVF (ФНЧ/ПФ/ФВЧ, резонанс), ADSR2 → срез, velocity → срез.
- 2 LFO, вибрато от mod wheel.
- Сверка RTL с Python-моделью по WAV.
- **Готово, когда:** звучат классические пэды, басы и «квакающий» фильтр.
- **Статус:** RTL, прошивка и тесты готовы: SVF и ADSR2 — в движке (этап 3), `mod_unit` (2 LFO + матрица
  из 8 маршрутов, побитово = `synthmodel.modunit`), вибрато от mod wheel, ENV = огибающая последнего нажатого
  голоса, GATE = есть нажатые клавиши. Прошивка: таблица параметров (`fw/patch.c`) и консоль UART
  (`set/get/list/route/note/off`). Системные тесты: вибрато, огибающая фильтра.
- **Найдено и исправлено тестами:** DECAY к sustain = 0 уводил уровень ниже нуля (округление вниз
  `(T − e) >> 14`), в RTL это заворачивалось в огромное значение → щелчки. Уровень ограничен снизу нулём
  в модели и RTL, добавлен регрессионный тест. Память голосов очищается после сброса.
- **Решения этапа 4:** синус LFO — параболическая аппроксимация (ошибка ≤ 6 %, без ROM); случайный LFO —
  xorshift32 при каждом переполнении фазы; выходы блока модуляции движок защёлкивает на следующем
  `audio_tick` (задержка 1 отсчёт).

### Этап 5. Панель управления
- SPI-контроллер + MCP3208: 8 потенциометров → параметры (сглаживание, гистерезис).
- Декодеры энкодеров, драйвер ST7789, шрифт с кириллицей.
- Каркас меню, построенный из дескрипторов параметров.
- **Готово, когда:** звук настраивается без компьютера.
- **Статус:** RTL, прошивка и тесты готовы (в симуляции): опрос MCP3208, энкодеры, контроллер ST7789,
  шрифт 8×16 с кириллицей (GNU Unifont, OFL/GPL с исключением для встраивания), меню из дескрипторов,
  консольные команды `screen`, `panel`. Проверено: кадр дисплея попиксельно, задержка MIDI при нагрузке
  на экран ≤ 0.7 мс. На железе: пины панели не назначены (Gowin расставит сам; HO-01), проверить
  инициализацию конкретного модуля ST7789 (смещения 40/53, инверсия), направление энкодеров, шаг EC11.
- **Решения этапа 5:** ручки подхватывают параметр при первом повороте («jump on move»), с мёртвыми зонами
  по краям хода; сглаживание в RTL начинается с первого измерения (нет «разгона» после сброса);
  экран — текстовая модель 30×8 ячеек, отрисовка неблокирующая; SPI ручек и дисплея — раздельные шины.

### Этап 6. Связь с АВК (ключевой этап)
- АЦП входов (2× SAR, 192 кГц → децимация 48 кГц), нормировка ±10 В ↔ ±1.0.
- Вход СИНХР: измерение периода, фронт → триггер нот, такт для LFO.
- Шина сигналов, выходной микшер, ВЫХ2 (второй канал ЦАП).
- Матрица модуляции: ВХ1/ВХ2 → высота / срез / громкость.
- Вывод LFO / огибающей / gate на ВЫХ2 — модуляция АВК от синта.
- Интерфейс слота + слот MATH (A·B, A/B, |A|, …) — проверка архитектуры слотов.
- **Готово, когда:** генератор АВК модулирует фильтр синта, огибающая синта управляет блоком АВК, слот MATH повторяет умножитель АВК.
- **Статус:** RTL, прошивка и тесты готовы (в симуляции). `avk/adc_in.sv`: два AD7091R (общие CONVST/CS/SCLK),
  4 измерения на отсчёт, калибровка `x = sat18(((code − OFFSET)·GAIN) >> 16)`, КИХ-дециматор 64 отвода
  (Кайзер β = 7, 21.5 кГц), задержка 1 отсчёт; `avk/sync_in.sv`: фильтр дребезга, счётчик фронтов, период
  в тактах; `avk/fx_bus.sv`: шина S0 синт, S1 ВХ1, S2 ВХ2, S3 LFO1, S4 LFO2, S5 СИНХР (±1), S6 ENV, S7 GATE,
  S8+k — выход слота k; ВЫХ = softclip(Σ GAIN·S + DC), ВЫХ2 = softclip(S[SEL2]·GAIN2 + DC2);
  `avk/slot_math.sv`: A·B, A/B, |A|, A+B, A−B, min, max, A mod B, A·k+B. Все блоки бит-в-бит с моделью
  `synthmodel/avk.py`. Прошивка: параметры входов/ВЫХ2/слотов/СИНХР, 5 страниц меню, режимы СИНХР
  (LFO — сброс фазы LFO по фронту, нота — перезапуск ноты по фронту), команды `avk` и `cal` (калибровка
  нуля и масштаба входа). Системные тесты с моделями АЦП и СИНХР в тестбенче: кольцевой модулятор
  ВХ1·ВХ2 в слоте MATH, ВХ1 → высота тона, ВЫХ2 = GATE, частота СИНХР и запуск нот.
  На железе: пины АЦП и СИНХР не назначены (HO-01); калибровка входов по фактическому входному каскаду.
- **Решения этапа 6:** слоты выполняются по порядку, слот, читающий более поздний слот, видит его прошлый
  отсчёт; неизвестный TYPE_ID — сквозной проход A; ВЫХ2 по умолчанию — LFO1; нажатая клавиша (GATE)
  берётся из регистра GATE блока модуляции; режим «нота» от СИНХР повторно нажимает ту же ноту
  (перезапуск огибающих), а не «отпустить + нажать» — оба события попали бы в один отсчёт.
  Консоль: приём UART вычитывается целиком за проход цикла, отрисовка меню — не больше 2 ячеек за
  проход (иначе при 1 Мбод переполнялся FIFO приёма на 16 байт).

### Этап 7. Переход на Tang Nano 20K + память
- Top-level и распиновка 20K; контроллер SDRAM + арбитр портов слотов.
- (На 9K допустимо отладить то же на встроенной PSRAM — интерфейс памяти абстрактный.)
- Слот DELAY: обратная связь, dry/wet, время от энкодера и от СИНХР.
- Масштабирование до 32 голосов.
- **Готово, когда:** 32 голоса + 2 задержки, раздельно на ВХ1 и ВХ2, смешиваются на выходе.
- **Статус:** RTL, прошивка и тесты готовы (в симуляции). Порт внешней памяти (запрос удерживается до
  подтверждения) и арбитр `mem/mem_arb.sv` (слоты — приоритет, затем окно CPU `0x4000_0000`); бэкенды
  `mem/mem_bram.sv` (9K: 4096 × 18 бит = 85 мс) и `mem/sdram_ctrl.sv` (20K: встроенная SDRAM 2M × 32,
  43 с; ACTIVE → READ/WRITE с автоподзарядом, регенерация каждые 7.8 мкс). Контроллер SDRAM проверен
  против модели, контролирующей tRCD/tRC/tRP/tWR/CL/регенерацию/инициализацию (модель ловит
  намеренно испорченные параметры). Слот DELAY (TYPE_ID 2): время, обратная связь, wet/dry, бит-в-бит
  с моделью при случайной задержке памяти. Прошивка: память делится поровну между задержками,
  параметры `dly1*`/`dly2*` (вход, время в мс, повтор, уровень), время от периода СИНХР (`dlysync`),
  команда `mem`. Прошивка переведена на целочисленную арифметику (без soft-float, −5 КБ).
  Системные тесты: эхо 50 мс с затуханием 50 %, время задержки от СИНХР 10 Гц, доступ CPU к памяти.
  PSRAM 9K не используется (нужен IP Gowin); 32 голоса на 20K — параметр `NUM_VOICES`, проверить
  утилизацию и тайминг синтезом. На железе: фаза такта SDRAM (HO-07).
- **Решения этапа 7:** одно слово памяти на отсчёт (18 бит в 32-битном слове); слоты выполняются
  по очереди, поэтому порт памяти шины — порт текущего слота без арбитража между слотами; задержка
  работает и в обходе (линия остаётся заполненной); тактовый сигнал SDRAM синфазен `clk`.

### Этап 8. Эффекты P1
- CHORUS/FLANGER, REVERB.
- PolyBLEP, жёсткая синхронизация от СИНХР, sustain, остальная матрица модуляции, envelope follower, pitch CV на ВЫХ2.
- **Статус:** готово в симуляции, кроме PolyBLEP. Слоты CHORUS (TYPE_ID 3: модулируемая задержка с
  треугольным LFO и линейной интерполяцией; хорус и флэнжер — одни и те же параметры) и REVERB
  (TYPE_ID 4: 4 гребенчатых фильтра с глушением + 2 всепропускающих, 5934 слова памяти) — бит-в-бит
  с моделью при случайной задержке памяти. Жёсткая синхронизация генераторов от фронта СИНХР
  (регистр HSYNC, по генераторам), следящий детектор огибающей ВХ1/ВХ2 — источник 10 матрицы
  модуляции (атака/спад), ВЫХ2 = высота последней ноты 1 В/окт (0 В = до первой октавы), sustain —
  с этапа 3. Прошивка: память — сначала реверберации и хорусу, остаток делят задержки; 5 новых
  страниц меню. На 20K — 6 слотов (MATH, MATH, DELAY, DELAY, CHORUS, REVERB), на 9K — 3 (без хоруса
  и реверберации: мало памяти). PolyBLEP (регистр BLEP, параметр `blep`, по умолчанию выключен):
  x = d/inc через pitch2inc от дробной части высоты (2^(17 − frac)) — 17 бит точности на всех
  высотах, коррекция на обоих скачках меандра; голос стал 32 такта (32 голоса — ~1060 из 2048);
  в модели снижает наложение спектра пилы/меандра 3.5 кГц на 14–15 дБ.
- **Решения этапа 8:** реверберация с фиксированными длинами линий (Freeverb, пересчёт на 48 кГц
  не делается); вход гребёнок ослаблен в 4 раза; ROOM 0.70…0.98, DAMP 0…0.4 из процентов в прошивке.

### Этап 9. Пресеты и сервис
- FAT на SD: сохранение и загрузка пресетов (синт + маршрутизация + слоты).
- Прошивка CPU во флеш из файла на SD.
- **Статус:** готово в симуляции. SPI-блок 11 для SD-карты (старт на 400 кГц, дальше 16.5 МГц); драйвер SD
  (SDHC/SDSC, одиночные блоки); FAT16/FAT32 — файлы корневого каталога, имена 8.3 (длинные имена
  пропускаются); пресеты `PRESETnn.BIN` — двоичная запись (значения по хешу имени параметра, переживает
  добавление/удаление параметров) + маршруты 1…7; команды `sd`, `ls`, `save`, `load`, `fwupdate`;
  страница меню «ПРЕСЕТЫ» (кнопка 2 — загрузить, 3 — записать). Обновление: FIRMWARE.BIN → флеш
  в формате загрузчика, с проверкой CRC перед записью заголовка. Тесты: хост-тесты FAT на образах
  независимого генератора `sw/tools/fatimg.py` (он же проверяет записанные образы), SD на модели карты;
  системные — модель SD в тестбенче: пресеты из консоли и с панели, обновление прошивки и загрузка
  с флеша. На железе: пины SD (HO-01), совместимость конкретных карт.
- **Решения этапа 9:** двоичный формат пресета вместо текстового — прошивка должна помещаться в 32 КБ
  ОЗУ 9K (текущий объём 30.6 КБ со стеком 2 КБ; компактное 64-битное деление вместо libgcc, буфер лога
  512 Б); запас — десятки байт. Для дальнейшего роста — ОЗУ 64 КБ на 20K (параметр `RAM_BYTES`)
  или отдельная урезанная сборка для 9K.

### Этап 10. Интеграция
- Калибровка ВХ/ВЫХ (смещение, масштаб), проверка при Volume = max.
- Демонстрационные схемы набора на АВК (для статьи).
