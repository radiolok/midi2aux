# AGENTS.md

Инструкции для AI-агентов (Claude Code, Kilo, Codex и др.), работающих с этим репозиторием.

## Проект

Сменные модули для аналогового компьютера **АВК-6**, серия «Музыкальная пауза». В репозитории два подпроекта:

| Подпроект | Статус | Где |
|---|---|---|
| **MIDI2AUX**: одноголосный MIDI → звук на Arduino Nano (ATmega328P) | готов, поддерживается | `fw/`, `platformio.ini`, `README.md` |
| **FPGA-синтезатор / процессор эффектов** на Tang Nano 20K (макет — 9K): полифония, ADSR, фильтр, эффекты на кольцевом буфере, связь с АВК в обе стороны | этап проектирования | `.plans/fpga-synth/`; далее `fpga/`, `sw/`, `hw/` |

Предыстория АВК-6 и MIDI2AUX — статья автора на Habr (timeweb, «Персональный аналоговый компьютер АВК-6»).

## Документы, которые нужно прочитать перед работой над FPGA-синтезатором

- `.plans/fpga-synth/trs.md` — ТЗ: требования, приоритеты P0/P1/P2, архитектура, карта памяти, открытые вопросы `O-xx`.
- `.plans/fpga-synth/plan.md` — план по этапам; каждый этап имеет критерий «Готово, когда».
- `.plans/fpga-synth/hw-requirements.md` — требования к узлам схемы (`Т-xx`), открытые вопросы `HO-xx`.
- `.plans/fpga-synth/panel-sketch.svg` — эскиз панели 120×90 мм (координаты в мм от левого верхнего угла).

Если решение меняет требования — обнови соответствующий документ в том же коммите. Закрытые открытые вопросы помечай как `~~вопрос~~ | **Решено:** …`, не удаляй.

## Сборка и проверка

MIDI2AUX собирается PlatformIO (см. `README.md`); для работы над FPGA-синтезатором PlatformIO не нужен и в CI не входит.

**FPGA-синтезатор** (подробно — `fpga/README.md`), из корня:
- `make lint` — `verilator --lint-only -Wall` (ядро и board-top с заглушками примитивов Gowin);
- `make sim` — тестбенч Verilator: поток MIDI-байтов из файла (31250 бод) → ядро → декодер I2S → WAV,
  затем pytest-тесты `fpga/sim/system/`: спектр, частота, THD, сравнение с Python-моделью → pass/fail;
- `make model` — pytest Python-моделей (`fpga/model/synthmodel`) и эталонные WAV;
- `make fw` — прошивка RISC-V (`riscv64-unknown-elf-gcc` или `riscv-none-elf-gcc`);
- `make unit` — юнит-тесты блоков RTL (cocotb + Verilator) против Python-моделей;
- `make test` — `lint` + `model` + `unit` + `sim`; прогоняй перед каждым пушем;
- `make luts` — перегенерировать таблицы RTL из модели (сгенерированные файлы не правь руками);
- битстримы собирает **Gowin EDA** локально у автора (`make bitstream-9k|20k`, `gw_sh`); в CI Gowin EDA нет.

CI (GitHub Actions) — обязателен и должен оставаться зелёным: линт, симуляция, сборка прошивки RISC-V.

## Ключевые технические решения (не менять без согласования)

| Параметр | Значение |
|---|---|
| Машинная единица АВК | ±10 В ↔ ±1.0 в цифре |
| Полная шкала входов/выходов | ±12.5 В (МЕ = 0.8 FS) |
| Частота отсчётов | ≈ 48 кГц от PLL (кварц 27 МГц); таблица нот считается от фактической fs |
| Разрядность | 18 бит внутри (`DATA_W`), 12 бит на АЦП входов (`ADC_W`) |
| Входы/выходы | связь по постоянному току, разделительных конденсаторов нет |
| Число голосов | параметр `NUM_VOICES` (цель 32 на 20K), голоса считаются с разделением по времени на общем конвейере |
| Эффекты | слоты со стандартным интерфейсом на общей шине сигналов; новый эффект = RTL-модуль + строка в списке слотов + дескриптор в прошивке |
| Разделение | звуковой тракт, MIDI UART и парсер — RTL; распределение голосов, меню, пресеты — C на софт-процессоре (PicoRV32) |
| MIDI | omni (все каналы), разъём TRS Type A |
| Toolchain | Gowin EDA; RTL переносимый, примитивы производителя — только в обёртках `fpga/boards/` |

## Правила

- **Язык:** документация и планы — на русском. Идентификаторы в коде — английские. Комментарии в коде — лаконично, в стиле окружающего кода.
- **Не трогай `fw/`** (MIDI2AUX), если задача не про него: устройство рабочее и используется.
- **RTL:** синтезируемый SystemVerilog/Verilog без специфичных для производителя конструкций вне `fpga/boards/`; каждый новый блок — с тестбенчем Verilator и, для DSP-блоков, со сравнением с Python-моделью.
- **Параметризуй**, а не хардкодь: число голосов, слотов, разрядности, целевую плату.
- **Железо:** схему и плату в KiCad рисует автор проекта. Задача агента — требования к узлам, расчёт номиналов, проверка схемы по `hw-requirements.md`, а не генерация файлов KiCad без запроса.
- **Коммиты:** короткий заголовок на английском в повелительном наклонении («Add …», «Fix …»), при необходимости — тело с деталями. Один логический шаг — один коммит.
- Не создавай PR и не пушь в `master` без явной просьбы.
