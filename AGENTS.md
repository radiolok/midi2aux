# AGENTS.md

Инструкции для AI-агентов (Claude Code, Kilo, Codex и др.), работающих с этим репозиторием.

## Проект

Сменные модули для аналогового компьютера **АВК-6**, серия «Музыкальная пауза». В репозитории два подпроекта:

| Подпроект | Статус | Где |
|---|---|---|
| **FPGA-синтезатор / процессор эффектов** на Tang Nano 20K (макет — 9K): 32 голоса, 2 генератора + шум, фильтр, 2 ADSR, LFO и матрица модуляции, эффекты в слотах (MATH, DELAY, CHORUS, REVERB), связь с АВК в обе стороны, панель с меню, пресеты на SD | этапы 0–9 готовы **в симуляции**; дальше — железо: Ж0 (ПО к железу), часть А (стенд на отладочных платах), часть Б (готовый блок) | описание — `README.md`; `fpga/`, `sw/`, `.plans/fpga-synth/`; `hw/` — схема и KiCad |
| **MIDI2AUX**: одноголосный MIDI → звук на Arduino Nano (ATmega328P) | готов, поддерживается | `fw/`, `platformio.ini`, `docs/midi2aux.md` |

Предыстория АВК-6 и MIDI2AUX — статья автора на Habr (timeweb, «Персональный аналоговый компьютер АВК-6»).

## Документы, которые нужно прочитать перед работой над FPGA-синтезатором

- `README.md` — что умеет модуль: голос, фильтр, модуляция, эффекты, меню (для пользователя).
- `.plans/fpga-synth/plan.md` — **текущая работа: железо.** Ж0 (подготовка ПО), часть А (стенд на отладочных
  платах, А1–А5), часть Б (готовый блок, Б1–Б5): что собрать, что где проверяется, критерии, схемы стендов,
  таблица «Результаты измерений».
- `.plans/fpga-synth/done-sim.md` — журнал этапов 0–9 (сделано в симуляции) с принятыми решениями.
- `.plans/fpga-synth/trs.md` — ТЗ: требования, приоритеты, архитектура, карта памяти, открытые вопросы `O-xx`.
- `.plans/fpga-synth/hw-requirements.md` — требования к узлам схемы (`Т-xx`), открытые вопросы `HO-xx`.
- `fpga/README.md`, `fpga/sim/README.md`, `sw/README.md` — устройство RTL, тестов по этапам, прошивки и консоли.

Если решение меняет требования — обнови соответствующий документ в том же коммите. Закрытые открытые
вопросы помечай как `~~вопрос~~ | **Решено:** …`, не удаляй.

  boot/ fw/ lib/   # загрузчик в ROM, прошивка, общий рантайм
  test/            # хост-тесты (gcc + ASan/UBSan)
  tools/           # load.py (загрузка по UART), fatimg.py (образы FAT), ui_pages.c, bin2rom.py …

## Сборка и проверка

MIDI2AUX собирается PlatformIO (см. `docs/midi2aux.md`); для FPGA-синтезатора PlatformIO не нужен.

FPGA-синтезатор, из корня (Ubuntu 24.04: verilator 5.020, gcc-riscv64-unknown-elf, Python 3 с
numpy, scipy, matplotlib, pytest, cocotb 1.9.2 — `fpga/requirements.txt`):

| Команда | Что делает |
|---|---|
| `make test` | `lint` + `model` + `swtest` + `unit` + `sim` — то же, что CI; **прогоняй перед каждым пушем** (~25 мин) |
| `make lint` | `verilator --lint-only -Wall`: ядра и board-top обеих плат |
| `make model` | pytest моделей + эталонные WAV |
| `make swtest` | хост-тесты прошивки (включая FAT на образах `fatimg.py`) |
| `make unit` | юнит-тесты RTL (cocotb) против моделей, бит-в-бит |
| `make sim` | системные тесты: ядро целиком, прошивка в ОЗУ, модели MIDI/UART/флеша/панели/АЦП/СИНХР/SDRAM/SD |
| `make fw`, `make bootrom` | прошивка; пересборка `boot_rom.sv` (CI проверяет, что он актуален) |
| `make luts` | таблицы RTL из модели (сгенерированные файлы руками не правь) |
| `make plots`, `make readme-img` | графики для `fpga/sim/README.md` и картинки `README.md` |
| `make bitstream-9k|20k` | Gowin EDA, только у автора; в CI Gowin нет |

Отдельный тест: `python3 -m pytest -q fpga/sim/system/test_synth_core_fx.py`; одна cocotb-сборка
кешируется в `build/unit/`, системная — в `build/sim/obj/`.

CI (GitHub Actions) — обязателен и должен оставаться зелёным.

## Ключевые технические решения (не менять без согласования)

| Параметр | Значение |
|---|---|
| Машинная единица АВК | ±10 В ↔ ±1.0 в цифре (Q2.16 в 18 битах, 1.0 = 65536) |
| Полная шкала входов/выходов | ±12.5 В (МЕ = 0.8 FS) |
| Частота отсчётов | ≈ 48.34 кГц: sys_clk 99 МГц (PLL из 27 МГц), 2048 тактов на отсчёт; таблица нот — от фактической fs |
| Разрядность | 18 бит внутри (`DATA_W`), 12 бит на АЦП входов |
| Входы/выходы | связь по постоянному току, разделительных конденсаторов нет |
| Число голосов | параметр `NUM_VOICES` (32 на 20K, 16 на 9K), голоса по очереди на общем конвейере, 32 такта на голос |
| Эффекты | слоты со стандартным интерфейсом на общей шине сигналов; новый эффект = RTL-модуль + строка в `SLOT_TYPES` + код в прошивке |
| Разделение | звуковой тракт, MIDI UART и парсер — RTL; распределение голосов, меню, пресеты — C на PicoRV32 |
| MIDI | omni (все каналы), разъём TRS Type A |
| Toolchain | Gowin EDA; RTL переносимый, примитивы производителя — только в `fpga/boards/` |

## Как вносить изменения

**Любой DSP-блок:** сначала модель в `fpga/model/synthmodel` (она — спецификация арифметики,
описана в её docstring), потом RTL, потом юнит-тест бит-в-бит со случайными параметрами. Меняется
арифметика — меняются модель, RTL и тест в одном коммите.

**Новый параметр синтезатора:** строка в `param_table` (`sw/fw/patch.c`, enum в `patch.h`),
применение в `synth.c`/`avk.c`, при необходимости — страница меню в `ui.c`. Меняется число страниц —
поправь ожидания в `sw/test/test_ui.c` и `fpga/sim/system/test_synth_core_panel.py`. Параметр попадает
в пресеты автоматически (по хешу имени).

**Новый эффект:** `fpga/rtl/avk/slot_*.sv` по образцу `slot_delay.sv` (интерфейс слота + порт памяти),
строка в generate-case `fx_bus.sv`, `TYPE_ID`, модель в `avk.py` (`Slot`), тест в
`fpga/sim/unit/test_avk_bus.py` с моделью памяти со случайной задержкой, код в `sw/fw/avk.c`
(выделение памяти, параметры), `SLOT_TYPES` в board-top, раздел в `README.md`.

**Регистры:** RTL-модуль документирует свои регистры в шапке; прошивка берёт адреса только из
`sw/include/hw.h`; карта памяти — в `trs.md` 8.2.

**Документация в том же коммите:** статус и решения — `plan.md` (железо) или `done-sim.md` (этапы 0–9), измерения — «Результаты измерений» в `plan.md`; что проверяется — `fpga/sim/README.md`
(с графиком, если он есть); что видит пользователь — `README.md` (и `make readme-img`); консоль — `sw/README.md`.

## Грабли, на которые уже наступали

- **ОЗУ прошивки — 32 КБ, свободно ~40 байт** (сборка падает с «no room for the stack»). Размер:
  вывод `make fw`. Перед добавлением кода — место (Ж0.5 в плане: 64 КБ на 20K). Нельзя soft-float
  (весь код целочисленный) и libgcc-деление 64 бит (своё в `lib/div64.c`).
- Консоль при 1 Мбод: приём UART вычитывается целиком за проход цикла, меню рисует ≤ 2 ячеек за
  проход — иначе переполняется FIFO приёма.
- cocotb: модель, отвечающая на запросы по фронту `clk`, видит значения с гонкой — отвечать по
  `FallingEdge`. `rtlrun.run` падает, если тесты не запустились (ошибка импорта модуля — тоже провал).
- Тестбенч системных тестов: ждать в сценарии UART конкретный ответ (`wait ok <имя>`), а не общий
  префикс; параметры шире 32 бит передаются в `vsys.build` как `int` (он сам делает sized literal).
- Слоты с памятью и 32 голоса укладываются в 2048 тактов на отсчёт с запасом ~2×; меняя расписание
  голоса (`voice_engine.sv`, поле `t`), проверь `status_and_timing` в `test_voice_engine.py`.

## Работа с железом

Схема в KiCad (`hw/kicad/`) сгенерирована скриптом `hw/kicad/tools/gen_kicad.py` по `hw/schematic.md`;
`hw/kicad/tools/check.py` сверяет netlist KiCad с задуманными цепями (нужен `kicad-cli`). Пока автор не начал править
схему руками, изменения схемы — правкой генератора и `schematic.md` в одном коммите, с прогоном `check.py`
и обновлением `avk_synth.pdf`; после ручных правок в KiCad генератор не запускать (см. `hw/kicad/README.md`).
Разводку платы делает автор проекта. Задача агента в частях А и Б плана: доработки кода,
которые шаги требуют (сначала воспроизвести ошибку в симуляции, потом исправить, тест оставить в CI),
разбор присланных отчётов Gowin, осциллограмм и записей звука, расчёт номиналов, проверка схемы по
`hw-requirements.md` (замечания — в `hw/review.md`), обновление плана и требований по результатам
измерений. Новые файлы KiCad (плата, другие проекты) не генерировать без запроса.

## Правила

- **Язык:** документация и планы — на русском. Идентификаторы в коде — английские. Комментарии в коде — лаконично, в стиле окружающего кода.
- **Не трогай `fw/`** (MIDI2AUX), если задача не про него: устройство рабочее и используется.
- **RTL:** синтезируемый SystemVerilog/Verilog без специфичных для производителя конструкций вне `fpga/boards/`; каждый новый блок — с тестбенчем Verilator и, для DSP-блоков, со сравнением с Python-моделью.
- **Параметризуй**, а не хардкодь: число голосов, слотов, разрядности, целевую плату.
- **Коммиты:** короткий заголовок на английском в повелительном наклонении («Add …», «Fix …»), при необходимости — тело с деталями. Один логический шаг — один коммит.
- Не создавай PR и не пушь в `master` без явной просьбы.
